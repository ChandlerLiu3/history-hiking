# 02 数据源

按「史料 → 地理 → 路网 → 影像」四层取数。每层都要能说出具体版本/链接。

## 史料层

| 源 | 取什么 | 注意 |
|---|---|---|
| 正史（史记/汉书/三国志/资治通鉴） | 行军路线、里程、日程、地名 | 里程常誇饰，需与地形校核 |
| 《水经注》 | 河谷、渡口、故道 | 河道千年有变，需对照古河道 |
| 《读史方舆纪要》 | 关隘、驿道、里距 | 明清人考据，需分辨转引 |
| 《元和郡县图志》 | 唐代州县里距 | 里距系统性偏大 |
| 地方志（府/州/县志） | 驿铺、古道、津渡 | 版本多，记版本与卷次 |
| 考古报告/碑刻 | 遗址坐标、道路遗存 | 最硬的证据 |

## 地理层

- **谭其骧《中国历史地图集》**：古今地名对照的基准，按朝代查。
- **CHGIS（复旦大学）**：可下载的点位与边界数据，适合批量锚定。
- **公开 DEM**：SRTM 30 m / ALOS 12.5 m，用于垭口、坡度、Least-cost path。
- **古河道与水库**：大型水库（如丹江口、三门峡）淹没段要单独标注，路径需「复原」并说明。

## 路网层

| 源 | 用途 | 获取 |
|---|---|---|
| OpenStreetMap | 步道、山路、垭口，可批量查询 | Overpass API；数据 ODbL，需署名 |
| 两步路（2bulu） | 国内驴友实测轨迹 | App 内搜关键词；导出需登录 |
| 六只脚（foooooot） | 老轨迹库 | 网页端可访问但要登录；轨迹下载走 `/trip/{id}/downloads/`。批量导出见 `tools/liuzhijiao_export.py` |
| Wikiloc | 可导出 GPX/KML，含航点 | 免费账号可下载 |

**用法**：轨迹不是史料证据，是「这条路今天能走」的证明。用它验证可行性，不用它替代史料定位。

## 影像层

- 历史卫星影像（Google Earth 历史图层、天地图历史影像）：看古道痕迹、机耕道变化。
- 1950s 美军 1:5 万地形图、日军测图：常保留已消失的小路。

## 检索技巧（优先用轨迹，不先自绘）

1. **两端地名同搜**，再加一个中间地貌点（垭口/关隘/寺/村）——命中率最高。
2. **古名今名并搜**：`褒斜道` 与 `斜谷`、`五丈原` 与 `五星村`。
3. **换平台搜**：两步路找不到，去 Wikiloc 用英文/拼音试（`Fenghuangling`、`Qinling`）。
4. **顺藤摸瓜**：找到一条好轨迹，点作者主页看他的其他轨迹；约伴活动页（`event/d-xxxx`）和社区帖常附轨迹图。
5. **App 优先**：两步路、六只脚的网页端有反爬或已失效，App 内检索最全；Wikiloc 网页可看统计与航点，下载 GPX/KML 需免费注册。
6. **看描述不看标题**：标题写「休闲」，描述里可能写「需绳索下降」。

## 轨迹成熟度速判

| 信号 | 可信 | 存疑 |
|---|---|---|
| 点数 | 15 km 有 800+ 点 | 15 km 只有 100 点 |
| 描述 | 有文字、照片、撤退点 | 只有一句「打卡」 |
| 来源 | 多个作者走向一致 | 仅一条孤轨迹 |
| 日期 | 近 1–2 年 | 5 年以上且无更新 |
| 一致性 | 与 OSM 步道/官方线路吻合 | 直线穿等高线 |

## 交叉校验规则

1. 任何锚点至少两源，否则置信度 ≤C。
2. 史料里距与 DEM 估算距离偏差 >25% → 必须解释。
3. 轨迹与史料走向冲突时，以史料定「应该走哪」，以轨迹定「今天能不能走」；两者都写进 uncertainty。
4. 同一地名多候选时，全部保留，标各自判据，禁止取平均坐标。

## 合规

- 国内 1:5 万地形图属涉密，一律不用；用公开 DEM。
- 引用他人轨迹：写平台、ID、作者、日期。
- OSM 数据：标注 © OpenStreetMap contributors, ODbL。
